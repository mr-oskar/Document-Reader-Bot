# AdPerform — حالة المشروع

آخر تحديث: 2026-08-11

## مرجع المنتج

الوثيقة الكاملة هي:
`attached_assets/وثيقه_متطلبات_انشاء_مشروع_ويب_اقراءه_كاملا__1786469415807.md`

الهدف هو Modular Monolith قابل للتوسع لمنصة CPV تربط المعلن بصانع المحتوى. الـMVP المطلوب في الوثيقة يركز على: التسجيل والأدوار، الحملات، التقديم، إرسال المحتوى، المراجعة البشرية، المحافظ/السجل، الإشعارات، والتحليلات الأساسية.

## ما تم إنجازه

### Foundation

- Workspace pnpm موجود ويحتوي على `artifacts/api-server` و`artifacts/mockup-sandbox`.
- تمت إضافة artifact ويب مستقل: `artifacts/adperform`.
- تم الحفاظ على Express API الحالي وhealth endpoint.
- وثائق التشغيل والمعمارية موجودة في `docs/`.

### Web MVP surface

- صفحة عامة للمنتج.
- تجربة دخول تجريبية مع اختيار الدور.
- مساحة المعلن: overview، الحملات، إنشاء حملة متعدد الخطوات، تفاصيل الحملة، المبدعون، التحليلات، المحفظة.
- مساحة المبدع: overview، سوق الحملات، تفاصيل الحملة والتقديم، الطلبات، المحتوى، التحليلات، المحفظة، المستوى.
- مساحة المراجع: قائمة الانتظار وشاشة المراجعة اليدوية.
- مساحة الإدارة: overview، المستخدمون، الحملات، المحتوى، المالية، الإعدادات.
- مركز إشعارات وإعدادات شخصية.
- حالات الثيم الفاتح/الداكن، RTL، وتجربة responsive.
- بيانات حملات إعلانية تجريبية مرئية محلياً دون الاعتماد على روابط صور خارجية.
- تفاعلات العرض الأساسية: تغيير الدور، التنقل، خطوات إنشاء الحملة، التقديم، إرسال رابط محتوى، قرارات المراجع، وطلب السحب.

## ما لم يُنفذ بعد (ولا يجب اعتباره موجوداً)

- مصادقة حقيقية، جلسات، OTP، refresh tokens، 2FA، وRBAC على الخادم.
- PostgreSQL domain schema وmigrations وseed حقيقي.
- APIs للحملات والتقديم والمحتوى والمراجعات والمحافظ.
- تخزين الملفات Object Storage وpresigned uploads وvideo workers.
- Redis/Queue/workers وWebSocket/SSE.
- Payment providers وescrow وdouble-entry ledger فعلي.
- Social platform providers وview validation وfraud engine.
- اختبارات unit/integration/E2E والـCI/CD.

## الخطوة التالية الموصى بها

**تثبيت Foundation API + قاعدة البيانات**:

1. تعريف OpenAPI للحملات، التقديم، المحتوى، المراجعة، المحفظة، والإشعارات.
2. إنشاء جداول users/organizations/campaigns/applications/content/reviews/wallet/ledger/audit.
3. إضافة جلسات ومصادقة وRBAC حقيقية.
4. استبدال local demo state تدريجياً بـTanStack Query hooks.
5. إضافة seed roles وحملة ومحتوى للمراجعة، ثم اختبارات الرحلتين الأساسية.

بعد ذلك تأتي طبقة التخزين/الرفع والمراجعة، ثم المالية والتحليلات، ثم الإدارة والتوسع.
